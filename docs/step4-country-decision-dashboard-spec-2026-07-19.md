# Step 4 국가별 수출 의사결정 대시보드 제안

- 작성일: 2026-07-19
- 대상 화면: `src/pages/Step4CountryDetail.tsx`
- 목적: 국가 일반정보를 읽는 화면이 아니라, 선택한 제품·HS·국가 조합에서 **견적/샘플 수출을 진행할지, 무엇을 먼저 확인할지, 추가 비용이 어느 정도인지** 빠르게 판단하는 화면
- 주요 사용자: 수출 전담자가 없거나 적은 산업단지 입주 중소기업의 대표·영업·수출 실무자
- 사용 시점: 후보국 비교 후 국가를 하나 선택했을 때, 견적 제출 또는 샘플 발송 전에 수시 사용

## 1. 결론

현재 화면은 신뢰할 만한 KOTRA·K-SURE 근거를 이미 수집하지만, 소스별 카드와 긴 문장으로 나뉘어 있어 사용자가 판단을 다시 조립해야 한다. 다음 구조가 적합하다.

1. 상단에는 `수출 적합도`, `관세·FTA`, `인증·규제·서류`, `결제·예상비용` 4개 판단 카드만 둔다.
2. 단일 100점 대신 `기회 점수`, `진행 상태`, `근거 충족률`을 분리한다.
3. 본문은 데이터 출처가 아니라 사용자 질문에 따라 `필수 요건`, `비용·결제`, `미확정·다음 행동`으로 묶는다.
4. `조회 0건`, `미실행`, `오래됨`, `API 오류`는 모두 다른 상태로 표시하고, 조회 0건을 “요건 없음”으로 해석하지 않는다.
5. 긴 국가정보, 규정 원문, API 기술명은 하단 `근거·원문` 아코디언/드로어에 넣는다.
6. 현재의 `상세 분석 실행`은 `데이터 갱신`으로 바꾸고, 별도의 `상세 분석` 버튼은 전체 근거 화면을 여는 용도로 사용한다.

## 2. 현재 화면 진단

### 잘 되어 있어 유지할 요소

- 제품명·국가·HS/HSK 문맥에 맞는 KOTRA 인증 및 수입규제 결과만 선별하는 서버 필터
- K-SURE 국가위험, 입력 업종 위험지수, 국가별 수출결제정보의 구분
- 데이터 상태를 `미실행/성공/0건/오류/오래됨`으로 구분하는 내부 모델
- 국가정보 원문을 요약과 접힘 영역으로 나누는 기존 `NationalInfoSection`
- 출처 URL과 조회 근거를 보존하는 구조
- 재사용 가능한 `ChecklistPanel`, Radix Accordion/Collapsible, Recharts, React Query, Zod

### 삭제하거나 축소할 요소

| 현재 요소 | 조치 | 이유 |
|---|---|---|
| 헤더의 판정·점수·위험 배지와 바로 아래 진입장벽 판정 | 하나의 `진행 상태`로 통합 | 같은 판단이 두 번 반복되고 서로 다른 배지가 충돌할 수 있음 |
| `포함 여부: 기본 후보군 포함` | 삭제 | 후보가 된 내부 과정이지 현재 국가에서 수출을 진행할지 판단하는 근거가 아님 |
| 편입 사유·후보 편입 신호·대안시장 | 국가 상세에서는 접거나 후보국 비교 화면으로 이동 | Step 3의 비교 정보이며 Step 4의 실행 판단을 흐림 |
| `DS00000128`, API/cache 같은 기술명 | 기본 화면에서 삭제하고 출처 상세에만 표시 | 사용자 행동과 무관한 내부 용어 |
| 우측 `AI 상태` | `분석 데이터 상태`로 이름 변경 후 접기 | 사용자는 AI 자체보다 어떤 데이터가 최신인지가 중요함 |
| 인증/규제의 큰 0건 카드 | `미확정 사항` 한 줄과 체크리스트로 축소 | 빈 카드가 화면을 차지하며 0건이 면제로 오해될 수 있음 |
| 국가 일반정보와 Top 10 수입품목 전체 | 선택 HS와 직접 관련된 최대 3개 요약만 기본 노출 | 선택 제품과 무관한 일반정보는 판단 속도를 낮춤 |
| 항상 보이는 우측 근거 패널 | 기본은 접고 `근거·출처` 드로어로 전환 | 데스크톱 본문 폭을 넓히고 다음 행동을 우측 레일에 배치하기 위함 |

### 반드시 추가할 요소

- 제품명, 한국 HSK, 목적국 세번, 기준일을 함께 보여주는 `분석 범위`
- `근거 충족률`: 확인/추정/미확정 항목 수와 마지막 갱신 시각
- 예상 MFN 세율, FTA 특혜세율, 협정명, 원산지 충족 상태
- 필수 인증·수입규제·한국 측 수출요건·목적국 통관서류를 한 표로 합친 `필수 요건 매트릭스`
- 물류, 보험, 관세, 수입세, 인증, 통관, 환율 버퍼를 포함한 `추가비용 범위`
- 미확정 항목에서 자동 생성되는 사용자 체크리스트
- 제재 대상 국가/거래상대방 및 전략물자 사전검토 상태
- 각 사실의 `출처`, `기준일`, `적용 범위`, `확정 수준`

## 3. 권장 화면 구조

### 3.1 데스크톱 와이어프레임

```text
┌ 미국 · 반도체 집적회로 · HSK 8542.31-xxxx ─ 기준 2026-07-19 ┐
│ 근거 6/10 확인 · 2개 추정 · 2개 미확정   [데이터 갱신] [상세 분석] │
├──────────────┬──────────────┬──────────────┬──────────────┤
│ 조건부 추진   │ 예상 관세·FTA │ 인증·규제·서류│ 결제·추가비용  │
│ 기회 82/100   │ MFN 2.5%     │ 필수 1/검토 2 │ 국가등급 1     │
│ 차단 0/확인 3 │ FTA 0% 가능  │ 서류 3/5 준비 │ +8~13% 추정    │
├─────────────────────────────────────┬─────────────────┤
│ 핵심 판단 근거: 긍정 3 · 위험 3      │ 다음 행동       │
│ 필수 요건 매트릭스                   │ 체크리스트 0/6  │
│ - HS/관세/원산지/인증/규제/제재/서류  │ 우선순위·담당·링크│
├─────────────────────────────────────┼─────────────────┤
│ 결제 위험과 비용 시나리오             │ 미확정 3건       │
│ 비용 항목별 범위·포함 여부·기준 통화  │ 확인 기관/버튼   │
├─────────────────────────────────────┴─────────────────┤
│ 시장 근거 요약 · 국가정보 요약 · 규정 원문 · 모든 출처 [펼치기]   │
└───────────────────────────────────────────────────────┘
```

- 본문은 12열 중 8열, 우측 체크리스트는 4열의 sticky 레일로 구성한다.
- 모바일은 `진행 상태 → 다음 행동 → 관세·FTA → 필수 요건 → 비용·결제 → 근거` 순서의 단일 열로 바꾼다.
- 상단 4개 카드를 누르면 해당 본문 섹션으로 이동한다. hover에만 의존하지 않는다.

### 3.2 상단 분석 범위와 액션

항상 보여야 하는 정보:

- 국가명
- 제품명
- 한국 HSK 10자리 및 목적국 세번의 확인 상태
- 데이터 기준일/마지막 갱신 시각
- 근거 충족률: `확인 6 · 추정 2 · 미확정 2`

버튼:

- `데이터 갱신`: KOTRA·K-SURE 및 추가 API를 비동기로 갱신한다. 현재의 `상세 분석 실행` 역할이다.
- `상세 분석`: 모든 세부 근거, 원문, 점수 산식, 출처를 드로어 또는 별도 상세 뷰로 연다.
- `후보국 비교`: 대안시장과 후보 편입 신호는 이 링크를 통해 Step 3에서 확인한다.

### 3.3 수출 적합도

한 개의 평균 점수만으로 법적·실무적 수출 가능성을 표현하지 않는다.

| 표시 | 의미 | 예시 |
|---|---|---|
| 진행 상태 | 차단 조건과 미확정 조건을 반영한 행동 라벨 | `조건부 추진`, `추진 검토`, `보류` |
| 기회 점수 | 현재 시장성 중심의 0~100 점수 | `82/100` |
| 근거 충족률 | 필수 판단 항목 중 확인된 비율 | `6/10 확인` |
| 차단/확인 | 수입금지·제재·필수인증 같은 차단과 일반 확인을 분리 | `차단 0 · 확인 3` |

현재 `market 30 / cert 20 / regulation 20 / payment 20 / safety 10` 합계는 기회 점수로 유지할 수 있다. 다만 누락값이 있어도 합산값이 높게 보일 수 있으므로 다음 gate를 별도로 둔다.

- HS/목적국 세번 미확정
- 필수 인증 적용 여부 미확정 또는 인증 취득 불가
- 수입금지·전략물자·제재·거래상대방 제한
- FTA 세율을 사용했지만 원산지결정기준 미확인
- 국가별 결제 데이터 부재
- 관세·물류·수입세가 빠진 비용 계산

표현 예시: `기회 높음 82점 · 수출 준비도 미완료 · 확인 3건`.

### 3.4 관세·FTA 카드

기본 노출:

- 목적국 세번과 확인 수준
- MFN 기본세율
- 가능한 FTA 협정명과 특혜세율
- 절감 예상: `2.5%p`
- 원산지 상태: `협정 있음 · 원산지 충족 미확인`
- 근거 기준일과 `추정/공식` 상태

중요한 문구 규칙:

- 협정 존재만으로 `FTA 적용 가능`이라고 쓰지 않는다.
- `FTA 세율 적용 후보`와 `원산지 충족 확인 완료`를 구분한다.
- 세번, 원산지, 쿼터, 세이프가드가 미확정이면 `예상 세율`로 표시한다.

상세 펼침:

- 품목별 원산지결정기준
- 필요한 원산지 증빙(BOM, 원산지확인서, 원산지증명서 등)
- 수입국 공식 관세표 링크
- 세율 기준일, 협정/일반세율 비교

### 3.5 필수 요건 매트릭스

데이터 출처별 카드 대신 아래 행을 한 표에 묶는다.

| 요건 | 상태 | 핵심 결과 | 다음 행동 | 출처/기준일 |
|---|---|---|---|---|
| HS/목적국 세번 | 확인 필요 | 한국 HSK만 확정 | 수입자/관세사와 목적국 세번 확인 | 관세청/WCO |
| 관세·FTA | 추정 | MFN 2.5%, FTA 0% 후보 | 원산지결정기준 확인 | 목적국 관세당국 |
| 해외인증 | 검토 필요 | 직접 매칭 0건 | 현지 인증기관/KOTRA 무역관 확인 | KOTRA |
| 수입규제 | 확인 | 무역구제 매칭 0건 | 0건은 규제 없음이 아님을 표시 | KOTRA/UNCTAD |
| 한국 수출요건 | 확인 필요 | 세관장확인/전략물자 후보 | 허가 대상 여부 확인 | 관세청/KOSTI |
| 제재·거래상대방 | 미실행 | 국가/상대방 스크리닝 필요 | 회사명·대표자·최종사용자 입력 | UN/OFAC/CSL |
| 통관서류 | 일부 준비 | 기본 3개, 조건부 2개 | 서류 업로드 또는 완료 체크 | 목적국 공식 안내 |

상태 체계는 화면 전체에서 네 가지로 통일한다.

- `확인`: 적용 범위와 기준일을 확인한 공식/직접 근거
- `추정`: 통계·범위·비공식 계산에 기반한 값
- `확인 필요`: 0건, 부분매칭, 사용자 입력 부족
- `이용 불가`: API 오류, 만료, 지원 국가 아님

### 3.6 결제 위험과 주요 예상 비용

결제 위험 기본 노출:

- K-SURE 국가 신용등급과 평가일
- 입력 업종 위험지수
- 국가별 평균 결제기간, 연체율, 주요 결제조건
- 국가별 결제 데이터가 없으면 전세계 집계로 대체하지 않고 `국가 데이터 없음` 표시
- 권장 결제 보호조치: 선지급, 신용장, 수출보험 검토 등. 규칙 기반 권고임을 표시

비용 계산에 필요한 사용자 입력:

- 거래금액/수량
- Incoterms
- 출발지·도착지 또는 항구/공항
- 운송 방식, 중량, 부피
- 보험 포함 여부
- 결제 통화
- FTA 원산지 충족 여부

비용 항목:

| 비용 | 기본 상태 | 계산 방식 |
|---|---|---|
| 국제운송비 | 추가 API 필요 | 노선·모드·중량/부피 기반 범위 |
| 보험료 | 사용자 입력/추정 | 운송가액 비율 또는 견적 |
| 관세 | 추가 API 필요 | 과세가격 × 적용세율 |
| 수입 VAT/GST·기타세 | 국가별 추가 연동 필요 | 목적국 세법 및 과세표준 |
| 인증·시험 | KOTRA 일부 가능 | 확인된 비용만 사용, 나머지는 견적 필요 |
| 통관·브로커·항만비 | 견적 필요 | 기본값이 아닌 범위/미확정으로 표시 |
| 환율 버퍼 | 환율 API 필요 | 기준환율과 사용자가 정한 변동 버퍼 |

결과는 단일 숫자보다 `추가비용 +8~13%`, `총 도착원가 1,080만~1,130만원`처럼 범위로 표시하고, 포함되지 않은 항목을 바로 아래에 적는다.

### 3.7 미확정 사항과 다음 실행 단계

미확정 항목은 단순 경고가 아니라 실행 가능한 작업으로 변환한다.

예시:

1. `목적국 10자리 세번 확인` — 관세 담당 — 최우선
2. `한·미 FTA 품목별 원산지기준과 BOM 대조` — 생산/구매 담당
3. `제품 용도 기준 인증 필요 여부 재확인` — KOTRA 무역관/현지 시험기관
4. `수입자와 필수 통관서류 확인` — 해외영업 담당
5. `거래상대방·최종사용자 제재 스크리닝` — 계약 전 필수
6. `FOB/CIF 운송 견적 2건 확보` — 물류 담당

체크리스트 요구사항:

- 프로젝트 + 국가 + 제품/HS 버전별로 DB에 저장
- HS 또는 제품 용도가 바뀌면 관련 완료 항목을 `재확인 필요`로 되돌림
- 각 항목에 우선순위, 담당자, 상태, 원문 링크, 완료일을 저장
- 미확정 근거가 해소되면 자동 완료 후보로 표시하되 사용자가 최종 확인
- `상세 분석`에서 근거를 읽은 뒤 바로 체크리스트로 돌아갈 수 있음

### 3.8 긴 국가정보와 규정 원문

기본 화면에서는 섹션별 최대 3개 완결 문장만 보여준다.

- 직접 관련: 선택 제품/HS와 직접 일치
- 공통 참고: 통관·결제·계약에 공통으로 필요한 내용
- 조건부 확인: 제품 사양·용도·수입자에 따라 달라지는 내용

하단 `근거·원문` 영역에서만 다음을 펼친다.

- KOTRA 국가정보 원문
- 인증 절차·필요서류 원문
- 수입규제 상세 원문
- K-SURE 세부 수치
- 시장 통계 상세
- 모든 출처 URL, 조회일, 적용 범위

Top 10 수입품목은 선택 HS 2/4/6자리와 관련이 있을 때만 기본 요약에 사용하고, 전체 표는 상세로 이동한다.

## 7. 권장 기술 구조

### 7.1 데이터 모델

단일 `total_score` 외에 다음 정규화 모델이 필요하다.

```ts
type EvidenceStatus = "confirmed" | "estimated" | "unresolved" | "unavailable";

interface DecisionFact {
  projectId: string;
  countryCode: string;
  productId: string;
  hsVersion: string;
  factType: "tariff" | "fta" | "certification" | "regulation" | "document" | "payment" | "cost" | "sanction";
  status: EvidenceStatus;
  value: unknown;
  scope: "product" | "hs" | "country" | "global";
  sourceId: string;
  sourceUrl?: string;
  observedAt?: string;
  fetchedAt: string;
  validUntil?: string;
}
```

추가 테이블/뷰:

- `country_decision_facts`: 정규화된 판단 사실과 상태
- `country_cost_scenarios`: Incoterms·수량·운송모드별 비용 시나리오
- `country_action_items`: 사용자 체크리스트, 담당자, 완료일, 근거 버전
- `external_dataset_versions`: 제재목록·KOSTI·UNCTAD·TARIC 배치 버전과 checksum

### 7.2 수집 구조

- 브라우저에서 외부 API를 직접 호출하지 않고 Supabase Edge Function에서 키와 quota를 관리한다.
- 현재 45초짜리 `country-detail` 단일 호출은 `tariff`, `compliance`, `payment`, `market`, `sanctions`, `cost` provider로 분리하고 병렬 갱신한다.
- 기본 화면은 마지막 성공 snapshot을 즉시 보여주고 섹션별 갱신 상태를 반영한다.
- API 오류가 기존 성공값을 지우지 않도록 하고, 기존값에는 `오래됨`을 표시한다.
- HS/제품/국가가 바뀌면 이전 근거를 새 문맥의 근거로 재사용하지 않는다.

| UN Comtrade | 월/분기 또는 신규 공표 확인 |
| UNCTAD NTM | 월 1회 메타데이터 확인, 국가별 기준연도 표시 |
| KOSTI HSK 연계표 | 주 1회 메타데이터 확인, 새 연간 파일 자동 수집 |

### 7.3 라이브러리 판단

- 새 UI 라이브러리는 필요 없다. 현재 Radix Accordion/Collapsible, `ChecklistPanel`, Recharts, React Query, Zod로 구현 가능하다.
- `uncomtrade/comtradeapicall`은 공식 Python 참고 구현으로 유용하지만, 현재 Supabase Edge/Deno 런타임에는 REST JSON 호출이 더 단순하다.
- `trade-tariff-backend`는 client library가 아니라 전체 서비스이므로 API 모델 참고용으로 사용한다.
- `yente`는 대규모 fuzzy screening이 필요해질 때 별도 서비스로 배포한다. MVP 번들에 넣지 않는다.
- 오래된 비공식 HS npm/GitHub 데이터셋은 법적 판정 근거로 사용하지 않는다.

## 8. 구현 순서

### Phase 1 — 화면 재구성, 현재 데이터만 사용

1. 헤더 중복 판정 제거, `진행 상태/기회 점수/근거 충족률` 분리
2. KOTRA 인증·규제·K-SURE를 `필수 요건 매트릭스`로 재배치
3. 미확정 항목을 `ChecklistPanel`로 자동 생성하고 저장
4. 국가정보·규정 원문·API 상태를 하단 아코디언/드로어로 이동
5. `상세 분석 실행`을 `데이터 갱신`으로 변경하고 별도 `상세 분석` 버튼 추가

### Phase 2 — 무료/공식 데이터 보강

1. 한국수출입은행 환율
2. 관세청 세관장확인대상 물품
3. 최신 KOSTI HSK 연계표 자동 동기화
4. UN Comtrade 대상국 수입/경쟁국 통계
5. WITS 관세 추정 + 미국 USITC 공식 tariff connector
6. CSL/UN/OFAC 제재목록 동기화

### Phase 3 — 견적과 국가별 공식 connector

1. Freightos 물류비 추정
2. EU TARIC, UK Trade Tariff connector
3. UNCTAD TRAINS NTM
4. 업종별 openFDA/FCC connector
5. 필요 시 Easyship/Shippo 또는 WCO Trade Tools 상용 연동

## 9. 완료 기준

- 사용자가 첫 화면 10초 이내에 `진행 상태`, `핵심 근거`, `미확정 건수`, `다음 행동`을 말할 수 있다.
- 상단에는 4개 판단 카드 외의 상세 지표를 올리지 않는다.
- 모든 핵심 사실에 출처, 기준일, 적용 범위, 확정 수준이 있다.
- 조회 0건·미실행·오류·오래됨이 서로 다른 문구와 상태로 표시된다.
- 미확정 항목마다 최소 한 개의 실행 가능한 체크리스트 항목이 생성된다.
- 관세·FTA는 협정 존재, 예상 세율, 원산지 충족을 분리한다.
- 국가 결제 데이터가 없을 때 전세계 집계를 선택국 근거로 표시하지 않는다.
- 비용 합계에는 포함/제외 항목과 통화 기준일이 표시된다.
- 데스크톱과 모바일 모두 원문을 열지 않고 핵심 판단을 완료할 수 있다.
- 캐시된 기본 화면은 2초 이내 표시되고 외부 데이터 갱신은 비동기로 진행된다.

## 10. 테스트 시나리오

1. 모든 데이터가 준비된 국가
2. 인증/규제 매칭 0건인 국가
3. KOTRA만 성공하고 K-SURE가 실패한 부분 성공
4. 캐시가 오래된 국가
5. 관세는 있으나 FTA 원산지 미확정
6. 수입금지/제재/전략물자 후보가 있는 hard blocker
7. 국가별 결제 데이터가 없는 경우
8. 운송 입력이 부족해 비용을 계산할 수 없는 경우
9. HS 변경 후 기존 체크리스트 무효화
10. 모바일에서 체크리스트와 상세 원문 열기

## 11. 적용한 설계 스킬

- `information-architecture`: 사용자 어휘로 섹션을 재명명하고, 후보 선정 과정과 API 내부용어를 기본 화면에서 제거하며, 원문은 progressive disclosure로 이동했다.
- `dashboard-specification`: 단일 질문, 상단 2~4개 KPI, hero → context → diagnostic → detail 순서를 적용하고, 지표 수를 제한했다.
